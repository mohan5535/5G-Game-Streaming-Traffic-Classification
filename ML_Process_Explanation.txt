5G GAME-STREAMING TRAFFIC: PACKET DIRECTION CLASSIFICATION
===============================================================

PROJECT OBJECTIVE
-----------------
The objective of this project is to classify network packets from a 5G game-streaming session (GeForce NOW) into two packet directions: Uplink and Downlink.

The project uses packet size and timing-related features to identify whether a packet is transmitted from the client to the server (Uplink) or from the server to the client (Downlink).

The dataset was analyzed, cleaned, preprocessed, and used for Machine Learning model training, evaluation, and comparison.

5. TARGET LABEL CREATION
------------------------
The original dataset does not contain a predefined packet direction label.

Therefore, a binary target variable was created using source IP addresses.

Client IP:

Server IP addresses:

112.217.128.200
112.217.128.202

Classification rules:

If Source IP = 10.215.173.1:
    Uplink

If Source IP = 112.217.128.200 or 112.217.128.202:
    Downlink

6. REMOVING UNNECESSARY AND LEAKAGE-PRONE FEATURES
--------------------------------------------------
The following columns were excluded from the final Machine Learning features:

No.
Source
Destination
Protocol
Info
Time
source_file

Reasons:

Source and Destination:
These IP addresses were used to generate the target label. Including them as input features could cause target leakage.

Protocol:
Protocol information was not required for packet direction classification.

Info:
Contains packet descriptions and protocol-related hints.

No.:
Represents packet sequence information rather than useful packet characteristics.

Time:
The original timestamp was used to calculate inter-arrival time.

source_file:
Represents the original capture file information and is not required for the final classification.

The final model uses packet size and timing-related features.


7. FEATURE ENGINEERING
----------------------
Five numerical features were created for Machine Learning.

1. Length
   Represents the packet size in bytes.

2. iat
   Represents the inter-arrival time between consecutive packets in seconds.

3. len_roll_mean
   Rolling mean of packet Length over the last 10 packets.

4. len_roll_std
   Rolling standard deviation of packet Length over the last 10 packets.

5. iat_roll_mean
   Rolling mean of inter-arrival time over the last 10 packets.

These features help the model understand packet size patterns and network traffic timing behavior.

Final features:

Length
iat
len_roll_mean
len_roll_std
iat_roll_mean

9. CLASS IMBALANCE HANDLING
---------------------------
The original dataset contains significantly more Downlink packets than Uplink packets.

Original distribution:

Uplink   = 12.8%
Downlink = 87.2%

To handle class imbalance, class_weight="balanced" was used in the applicable classification models.

This approach assigns higher importance to the minority class during model training.

The original class distribution was retained in the training and testing samples.

18. IMPORTANT FINDINGS AND LIMITATIONS
--------------------------------------
Important findings:

- Tree-based models performed significantly better than Logistic Regression.
- Packet Length was the most influential feature.
- Inter-arrival Time also contributed significantly to classification.
- The tuned Decision Tree achieved a small improvement over the baseline Decision Tree.
- Cross-validation and test Macro F1 scores were very similar.

Limitations:

- The dataset covers only GeForce NOW traffic.
- The task is packet direction classification, not game-streaming service classification.
- Downlink packets are significantly more frequent than Uplink packets.
- The task may be relatively easy because downlink video packets are generally larger than uplink control packets.
- Classification is performed at packet level, not flow level.
- The models were trained using sampled portions of the original 7.3-million-packet dataset.

The reported performance should not automatically be interpreted as generalization to completely unseen network environments.

20. FINAL CONCLUSION
--------------------
This project demonstrates an end-to-end Machine Learning workflow for classifying Uplink and Downlink packets in a 5G game-streaming environment using GeForce NOW network traffic data.

The project includes:

- Loading and analyzing 7,338,316 network packets.
- Exploring network protocols and packet characteristics.
- Checking missing values and duplicate records.
- Creating Uplink and Downlink target labels.
- Engineering packet size and timing-related features.
- Performing time-based train-test splitting.
- Handling class imbalance using class weights.
- Training multiple Machine Learning models.
- Evaluating models using classification metrics.
- Performing five-fold TimeSeriesSplit validation.
- Optimizing the Decision Tree using RandomizedSearchCV.
- Comparing model performance.
- Analyzing the confusion matrix and feature importance.

Final comparison:

Logistic Regression          -> 73.11%
Decision Tree                -> 99.01%
Random Forest                 -> 99.00%
Histogram Gradient Boosting   -> 98.78%
Tuned Decision Tree           -> 99.10%

The Tuned Decision Tree was selected as the final model with 99.10% test accuracy and 0.9780 Macro F1 score.

The results demonstrate that packet size and timing-related features can effectively distinguish Uplink and Downlink traffic in the evaluated GeForce NOW dataset.
